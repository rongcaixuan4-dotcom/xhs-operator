# 「XHS 运营助手」操作手册要点

> 面向运维者 / 首次部署用户。完整架构见 `docs/架构设计.md`，需求见 `docs/PRD.md`。

## 1. 首次部署（Windows）

```bat
:: 1) 安装 Python 3.11+ 并加入 PATH
:: 2) 项目根目录执行：
pip install -r backend/requirements.txt
playwright install chromium
:: 3) 复制配置模板（可选，默认值即可跑）
copy backend\config.example.yaml backend\config.yaml
:: 4) 双击 start.bat（或 python run.py）
```

- 后端监听 `127.0.0.1:8787`，浏览器自动打开工作台。
- 数据全部落在 `data/`：SQLite（`data/xhs_assistant.db`）、采集图 `data/collected/`、二创图 `data/creations/`、截图 `data/screenshots/`、浏览器 profile `data/profiles/account_1/`。
- 日志：`logs/app.log`（5MB×5 轮转）。

## 2. 首次使用流程（对应 PRD 场景 A）

1. **设置页**（工作台右上导航未放，前端当前从 Dashboard 可加）：
   - `PUT /api/settings/ai/llm`：填 LLM base_url / api_key / model → 点测试；
   - `PUT /api/settings/ai/image`：生图配置（默认 `tt-image-2.5`，备选 banana 系）→ 点测试；
   - 状态灯变绿即连通。
2. **人设管理**：创建人设 → 点「设为生效」。
3. **知识库**：拖拽导入运营经验文档（txt/md/docx）或粘贴文本。
4. **采集与选题**：新增话题（关键词、时段、每日篇数）→ 点「立即采集一轮」验证。
5. **首次登录**：采集/发布第一次触发时会弹出真浏览器，**人工扫码登录小红书**一次，登录态长期保留在 profile 中。
6. **发布日历**：审核通过的稿件入队后按 `publish_slots`（默认 10:00/15:00/19:00）自动排期，也可手动指定时间。

## 3. 日常运维

| 事项 | 说明 |
|---|---|
| 人工审核 | 默认开启（`AppSetting.review_required`）。每天在「二创审核」页通过/驳回；驳回原因自动入知识库负样本 |
| 关闭审核 | `PUT /api/settings/app {"review_required": false}` → 二创稿自动入发布队列 |
| 告警 | 工作台「告警通知」：流水线环节失败 / 发布失败 / 周报待确认 |
| 发布失败 | 发布日历 → 失败任务 → 重试（≤3 次）；常见原因：未扫码登录、页面改版（截图在 `data/screenshots/`） |
| 周报 | 每周一 09:00 自动生成；确认改进项后写入知识库并在下周提示词中生效 |
| 流水线状态 | `GET /api/pipeline/status`，`GET /api/pipeline/history`（近 7 天） |

## 4. 定时任务一览（APScheduler）

| 任务 | 触发 | 说明 |
|---|---|---|
| 话题采集 | 每话题 `collect_times`（cron） | 采集 + 评分筛选 |
| 每日流水线 | `daily_run_time`（默认 08:00） | 监测→采集→筛选→二创→审核→发布→快照 |
| 数据快照 | 每 60 分钟 | 笔记级 + 账号级快照（每篇每日 ≥1 条） |
| 周复盘 | 每周一 09:00 | 生成报告 + 超期归档（>14 天 expired） |
| 发布到点扫描 | 每 10 分钟 | queued 且到点的任务执行发布 |
| 失败重试扫描 | 每 30 分钟 | failed 且重试 <3 的任务顺延 30 分钟重排 |

## 5. 安全红线（部署方与运维者必须知晓）

1. 系统只操作**真浏览器**页面：绝不逆向小红书签名算法，绝不导出 Cookie 直连写接口。
2. `ai_config.api_key` 接口返回一律脱敏（`sk-***last4`），明文只存本地 SQLite。
3. 单机使用：服务监听 127.0.0.1，勿将 8787 端口暴露公网。
4. 防重复：`SHA1(标题+图片字节指纹)` 数据库唯一约束 + 双重查重 + 发布后列表核查。

## 6. 已知待真机校准项（架构 UNCLEAR 清单）

1. 生图 `/images/edits` multipart 字段名（`extra.edits_image_field` 可兜底配置）。
2. 创作者中心「合集/@好友」选择器（发布引擎已留扩展位，不影响核心流程）。
3. 「曝光数」口径：读不到时快照退化为赞/藏/评（exposure 记 0）。
4. 页面选择器随平台改版需校准：全部集中在 `engines/collect.py`、`engines/publish.py`、`engines/snapshot.py` 顶部常量。
